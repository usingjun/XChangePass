# Task Template

## 목적

이 문서는 Codex가 XChangePass 프로젝트에서 하나의 작업을 수행할 때 따라야 하는 작업 흐름이다.

Codex는 바로 코드를 수정하지 않고, 기존 코드와 문서를 먼저 읽은 뒤 최소 변경으로 작업한다.

## 1. 작업 시작 전 읽기

작업을 시작하기 전에 아래 문서를 순서대로 읽는다.

1. AGENTS.md
2. docs/agent/project-context.md
3. docs/agent/xchangepass-rules.md
4. docs/agent/prompt-cache-rules.md
5. docs/agent/task-template.md

그다음 작업과 관련된 기존 코드를 읽는다.

## 2. 분석

코드를 수정하기 전에 아래 내용을 먼저 정리한다.

* 현재 코드 흐름
* 문제 지점
* 변경이 필요한 파일
* 영향을 받을 수 있는 도메인
* 정합성, 트랜잭션, 멱등성, 복구 관점의 위험
* 최소 변경 계획

## 3. 구현

구현 시 아래 규칙을 따른다.

* 기존 구조를 먼저 따른다.
* 불필요한 리팩토링을 섞지 않는다.
* 변경 범위를 작게 유지한다.
* 기존 네이밍과 코드 스타일을 유지한다.
* 비즈니스 로직이 바뀌면 테스트를 추가하거나 수정한다.
* 동시성, 정합성, 복구 관련 로직은 단순 성공 케이스만으로 끝내지 않는다.
* 실제 프로젝트에 없는 기술을 임의로 도입하지 않는다.

## 4. 검증

작업 후 가능한 경우 아래 명령을 기본 검증으로 실행한다.

```bash
./gradlew test
```

작업 성격에 따라 전체 테스트 대신 관련 테스트만 실행할 수 있다.

`./scripts/agent-check.sh`는 스크립트가 존재하는 경우에만 실행한다.

예시:

* 송금 로직 변경: 송금 정합성 테스트 실행
* 멱등성 변경: 중복 요청 테스트 실행
* 복구 배치 변경: 복구 대상/운영 예외 분리 테스트 실행
* 이상거래 탐지 변경: Redis 장애 및 Circuit Breaker 테스트 실행
* 통합조회 변경: 조회 성능 또는 페이징 테스트 실행

검증을 실행하지 못했다면 이유를 명확히 남긴다.

## 5. 작업 완료 보고

작업이 끝나면 아래 형식으로 보고한다.

### 변경 파일

* 변경한 파일 목록

### 변경 내용

* 무엇을 바꿨는지 요약

### 변경 이유

* 왜 이 변경이 필요한지 설명

### 검증 결과

* 실행한 테스트
* 성공/실패 여부
* 실패했다면 원인

### 남은 위험

* 추가 확인이 필요한 부분
* 추후 보완이 필요한 부분
